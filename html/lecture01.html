第 01 讲｜Agent 基础与全景

在很长一段时间里，构建自然语言处理应用的核心工作是训练或微调一个单体模型（Monolithic Model）：给定一段输入文本，模型一次性输出一段预测文本。然而，当我们希望 AI 真正替人完成复杂的工作——比如排查线上代码故障、核对几十封邮件并安排日程、或者在终端里完成多步数据分析——单次文本生成就显得捉襟见肘了。

这门课程的核心主题，正是如何完成从“调用单个语言模型”向“构建复合 AI 系统与自主智能体（Agentic Systems）”的工程跨越。作为全课程的开篇，本讲将梳理 Agent 概念的演进脉络，拆解现代 AI Agent 的五大核心组件，辨析固定工作流与自主 Agent 的设计边界，并探讨可靠性、安全与评测等关键挑战。

学习目标

  • 掌握 Agent 的基本解剖结构，理解大语言模型核心（LLM Core）、规划与推理（Planning & Reasoning）、记忆（Memory）、工具（Tools）与环境（Environment）之间的闭环反馈机制。
  • 区分复合 AI 系统（Compound AI Systems）、固定工作流（Workflows）与自主 Agent（Autonomous Agents）的控制流差异及适用场景。
  • 理解构建生产级 Agent 在长程可靠性、训练优化、安全边界与真实能力评测上的核心工程挑战。

知识讲解

1. 课程定位与学习方式

从模型到系统

构建一个可靠的 AI Agent，需要同时具备两种视角：模型视角（Modeling Perspective）与系统视角（Systems Perspective）。熟悉大模型的研究者了解模型如何预训练、微调、对齐与提示，而软件系统工程师则擅长设计高可靠的工具接口、运行时环境与容错基础设施。

在工程实践中，无论一个 Agent 系统外表多么复杂，其研发工作都可以归结为三根支柱：

  1. 系统（The System）：架构设计、控制流编排、工具接口定义与上下文管理。
  2. 数据（The Data）：训练样本、少样本示范（Demonstrations）、交互轨迹（Rollouts）与人类反馈。
  3. 评测（The Evals）：测试任务集、评分器（Graders）以及衡量成功率、成本、延迟与安全性的指标体系。

在动手堆叠框架之前，始终应当先定义清楚要解决什么问题、用什么任务数据和评测标准来检验系统是否真正奏效。

先备知识、教学团队与课堂安排

本课程采用“先底层实现，后抽象框架”的训练路径。在前几周，你将从零手写检索器、函数调用解析器与 Agent 主循环，亲身体验每一处边界条件；在此之后，再去理解 DSPy、LangGraph 等框架是如何将这些模式抽象化的。学习过程中建议结合课堂讲义、必读论文、两项代码作业（从零实现 Harness 与构建评测套件）、论文复现报告以及贯穿全学期的课程项目，将理论转化为可验证的系统工程能力。

AI 辅助学习与技能侵蚀

在学习构建 AI 系统的过程中，如何正确使用 AI 辅助编程是一个值得警惕的问题。Anthropic（Shen & Tamkin, 2026）针对 52 名软件工程师开展了一项随机对照实验（RCT）：让工程师学习一个全新的 Python 库，一组使用 AI 助手辅助编写代码，另一组完全独立探索。在随后的掌握度测验中，依赖 AI 辅助的工程师得分比独立学习组低了 17%（相当于差了两个字母等级），且差距最大的恰恰是资深工程师最核心的能力——代码调试与排错（Debugging）。

实验表明，用 AI 快速生成能跑通的代码，并不等于你真正理解了底层机制。因此，在完成本课程的作业与实验时，推荐遵循“先自行设计并预测输出 → 编写核心逻辑 → 借助工具调试验证 → 能够脱离代码独立复述设计权衡”的学习闭环。

诚信、出勤与资源边界

在工程实践与实验报告中，应当严格区分三个层次的工程事实：代码逻辑已编写完成、在离线确定性脚本模型（如 ScriptedLM）上通过控制流测试，以及在真实大模型与完整数据集上跑通端到端评测。诚实地记录每一次实验的配置、预算开销与失败案例，远比展示一段经过挑选的完美演示更有工程价值。

2. Agent 概念的历史

早期分布式与认知 Agent

“Agent”一词源于拉丁语 agens，意为“行动者（one who acts）”。在人工智能领域，这一概念并非伴随大语言模型才诞生，而是经历了半个多世纪的演化：

  • ACTOR 模型（Hewitt, Bishop & Steiger, 1973）：人工智能文献中最早系统使用 Agent 概念的工作之一，将计算系统建模为通过异步消息传递协作的独立计算单元。
  • 合同网协议（Contract Net Protocol, Smith, 1980）：将分布式系统中的任务分配建模为不同节点之间的招标、投标与协商过程。
  • 心智社会（Society of Mind, Marvin Minsky, 1986）：从认知科学角度提出，复杂的智能行为是由大量简单、无智能的底层微过程（Agents）相互协作与竞争涌现出来的。

这些早期探索奠定了“多主体通信、任务分解与协作”的思想基础，但当时的系统依赖人工编写的符号规则，尚不具备通用的自然语言理解与开放推理能力。

经典定义与自主性

进入 20 世纪 90 年代，研究者开始严格界定什么是一个“智能体”：

  • Pattie Maes（1994） 强调，自主 Agent 是在复杂、动态的环境中驻留，能够自主感知并采取行动以实现一系列目标的系统。
  • Wooldridge 与 Jennings（1995） 提出了著名的 Agent 四大特性：自主性（Autonomy，在无人类直接干预下运行并控制自身状态）、社交能力（Social Ability，与其他 Agent 或人类通信协作）、反应性（Reactivity，感知环境变化并及时响应） 与 主动性（Pro-activeness，不仅被动响应，还能主动采取目标导向的行动）。
  • Russell 与 Norvig（1995） 在经典教材《人工智能：一种现代方法》中给出了最广为人知的系统定义：Agent 是任何能够通过传感器（Sensors）感知环境，并通过执行器（Actuators）作用于环境的实体。

强化学习到语言 Agent

随后，强化学习（Reinforcement Learning, Sutton & Barto, 1998） 将这一概念形式化为“智能体—环境循环（Agent-Environment Loop）”：Agent 在每个时间步接收观测（Observation Ot）与奖励（Reward Rt），并输出动作（Action At）以最大化长期累积回报。从 DeepMind 在 Atari 游戏上取得突破的 DQN（Mnih et al., 2015）到围棋程序 AlphaGo，强化学习证明了在规则明确、奖励可密集计算的封闭环境中，这种闭环策略能达到超越人类的水平。

然而，传统强化学习策略很难泛化到开放的现实世界任务。转折点出现在大语言模型时代：

  1. GPT-3（2020） 展示了强大的上下文学习（In-Context Learning）与零样本泛化能力；
  2. MRKL 系统（2022） 提出将大语言模型与外部确定性模块（计算器、数据库、API）结合，实现模块化推理；
  3. ReAct（Yao et al., 2022年10月） 将语言模型的思维链推理（Reasoning）与外部工具动作（Acting）交织在同一个循环中；
  4. 紧接着，ChatGPT（2022年11月）、GPT-4（2023年3月）以及开源社区涌现的 BabyAGI、AutoGPT 引爆了以大语言模型为核心的现代 Agent 浪潮。

随着基础模型能力与测试时计算（Test-time Compute）的持续提升，现代 Agent 能够可靠自主完成的任务时长正在从几秒钟的单步问答，快速向数十分钟乃至数小时的复杂软件工程与研究任务延伸。

3. Agent 的组成与推理

核心、计划、工具、环境

如果把一个现代语言 Agent 拆开，它的标准架构由五个核心部分组成，形成一个持续运转的闭环：

  1. 大语言模型核心（LLM Core）：系统的“中枢大脑”，根据当前上下文中的提示词、历史记录与环境观测，生成下一步的内部推理或外部动作指令。
  2. 规划与推理（Planning & Reasoning）：在行动前分解复杂目标、分析约束条件，并在遇到阻碍时调整方案（对应 ReAct 中的 Thought）。
  3. 记忆（Memory）：保存和检索交互轨迹（traces so far）、领域知识与可复用技能，突破单次上下文窗口的长度限制。
  4. 工具（Tools）：系统的“执行器（Actuators）”，包括搜索引擎、代码解释器、文件读写接口、计算器、数据库查询等，使模型生成的文本指令能够转化为对外部世界的真实操作（对应 Act）。
  5. 环境（Environment）：Agent 所处的外部世界，如桌面操作系统、Web 浏览器、代码仓库、数据库或移动应用。环境在执行工具动作后产生状态变更，并将新的观测结果（Obs）反馈给 Agent。

值得注意的是，Agent 的动作（Actions）涵盖三种形式：调用外部工具、与环境交互，以及直接向用户返回自然语言回复。如果一个系统只生成了一份长篇计划却没有任何执行器与环境反馈，它完成的只是文本生成，而非真正的 Agent 行动。

推理的三个层次

在讨论“Agent 推理（Reasoning）”时，我们必须区分三个不同层次的概念：

  • 对人类而言：推理是演绎、类比、归纳与规划等真实的心智过程（Mental Processes）。
  • 对大语言模型而言：推理是模型在输出最终答案或动作前生成的中间文本序列（Intermediate Generations），它模仿了人类思维的语言表征，但并不等同于人类的意识过程。
  • 对 Agent 系统而言：推理是一种更新 Agent 自身内部状态的内部动作（Internal Action）。

为什么在从“观测（Observation）”到“动作（Action）”之间插入显式的推理步骤至关重要？设想你在做菜时看到盐罐空了（观测 Ot），如果你的动作直接是“向右转身（动作 At）”，从纯观测到动作的直接映射跨度极大，很难泛化。但如果在中间加入一步推理：“这道菜需要咸味，既然盐没了，我应该找酱油代替，而酱油在右边的橱柜里”，那么后续的“向右转 → 看到橱柜 → 打开橱柜”就顺理成章了。显式推理能同时提升系统的跨场景泛化能力（Generalization）与行为可控性（Alignment）。

Chain-of-Thought 与错误推理

思维链（Chain-of-Thought, CoT）通过让模型“一步步思考（Let's think step by step）”显著提升了数学与逻辑任务的表现。但在开放环境中，只推理不行动（Reason Only）有着致命的短板——事实幻觉（Hallucination）。

来看课件中的一个经典例子：

问题：除了 Apple Remote 遥控器之外，还有什么设备可以控制 Apple Remote 最初设计用来交互的那个程序？

  • 直接回答（Standard）：模型盲猜 iPod（错误）。
  • 纯思维链（Reason Only）：模型自信地推理道：“让我们一步步思考。Apple Remote 最初是设计用来与 Apple TV 交互的。Apple TV 可以由 iPhone、iPad 和 iPod Touch 控制。因此答案是 iPhone、iPad 和 iPod Touch。”

这段推理逻辑通顺、结构严密，但结论完全错误——因为第一步的前提就是模型编造的（Apple Remote 最初于 2005 年推出，设计用来控制 Mac 上的 Front Row 媒体中心程序，而非 2007 年才发布的 Apple TV）。在没有外部真实环境反馈的情况下，思维链一旦在早期步骤产生偏差，后续推理只会沿着错误前提越走越远。

ReAct：Reason → Act → Observe

为了解决纯推理的幻觉问题与纯行动（Act-only）缺乏目标规划的问题，ReAct（Yao et al., 2022） 提出了将推理与行动交织的范式：Reason（思考）→ Act（行动）→ Observe（观测）。

面对上面同一个问题，ReAct 的执行轨迹如下：

  1. Thought 1：我需要先搜索 Apple Remote，查明它最初是设计用来控制什么程序的。
    • Act 1：Search[Apple Remote]
    • Obs 1：Apple Remote 是苹果公司于 2005 年 10 月推出的遥控器……最初设计用于控制 Front Row 媒体中心程序……
  2. Thought 2：Apple Remote 最初用于控制 Front Row 程序。接下来我需要搜索 Front Row，看看还有什么设备能控制它。
    • Act 2：Search[Front Row]
    • Obs 2：未找到 [Front Row]。相似词条：['Front Row Seat to Earth', 'Front Row Motorsports', 'Front Row (software)', ...]
  3. Thought 3：直接搜 Front Row 没找到，我应该改搜 Front Row (software)。
    • Act 3：Search[Front Row (software)]
    • Obs 3：Front Row 是一款已停产的媒体中心软件……可由 Apple Remote 或键盘功能键控制。
  4. Thought 4：Front Row 软件由 Apple Remote 或键盘功能键（Keyboard function keys）控制，因此答案是键盘功能键。
    • Act 4：Finish[keyboard function keys]

通过这个轨迹可以看到 ReAct 的核心威力：当外部检索返回“未找到”时，模型能够根据观测调整查询词；而检索回来的真实证据又及时锚定了模型的推理方向，避免了凭空猜测。

Self-consistency

除了与环境交互，提升推理可靠性的另一条重要思路是自洽性采样（Self-Consistency, Wang et al., 2023）：对同一个问题使用思维链提示采样多条不同的推理路径（例如通过设置非零的 Temperature），然后在所有路径得出的最终答案集合中通过多数投票（Majority Voting）选出最一致的答案。其核心直觉是：复杂问题往往有多种正确的推导路径，而错误的推理更容易发散到不同的错误答案上。不过需要注意，Self-Consistency 会成倍增加推理 Token 成本，且当模型对某类事实存在系统性偏见时，多条路径仍可能一致投出错误答案。

Reflexion 与多 Agent 推理

当单次尝试失败时，如何让 Agent 从错误中吸取教训？

  • 语言自我反思（Reflexion, Shinn et al., 2023）：无需更新模型权重，而是让 Agent 根据外部环境返回的失败信号（如单元测试报错、任务超时或评分器反馈）生成一段自然语言反思摘要（Self-Reflection），将这段“经验教训”存入滑动记忆缓冲区，作为下一次尝试时的显式提示（Self-hints）。
  • 多智能体辩论（Multi-Agent Debate, Du et al., 2023）：让多个模型实例分别针对同一问题给出初始解答，随后相互审阅对方的推理过程并展开多轮辩论，最终收敛到更准确的结论。
  • 中心化编排（如 Microsoft Magentic-One）：由一个主导编排器（Orchestrator）负责全局规划与进度追踪，将子任务委派给网页浏览、代码执行、文件操作等专长子 Agent 协同完成。

4. 记忆的三种作用

为什么不能只加长上下文

既然现代大语言模型的上下文窗口已经扩展到数十万乃至上百万 Token，为什么 Agent 还需要专门的记忆架构？原因在于两点：第一，对于长周期、跨会话运行的 Agent，持续产生的事件流终究会撑爆任何固定窗口；第二，即使窗口装得下，过长的历史上下文也会导致高昂的计算成本与注意力分散（模型难以在海量陈旧信息中精准聚焦当前关键事实）。因此，记忆系统的核心不在于“把所有字节原封不动塞进提示词”，而在于设计合理的写入（Write）与读取（Read）机制。

受人类认知心理学的启发，Agent 的长期记忆通常按内容形态划分为三类：

记忆类型存储内容写入机制（Write）读取机制（Read）典型代表系统
情景记忆（Episodic Memory）具体经历与历史事件轨迹追加写入事件流（Append-only event streams）基于时间衰减、重要性与相关度的启发式检索Generative Agents (Park et al., 2023)
语义记忆（Semantic Memory）提炼出的事实、概念与世界知识由 LLM 对历史事件进行归纳与推理提炼基于语义相关性检索事实Mem0 / 知识库系统
程序性记忆（Procedural Memory）完成任务的技能、动作规则与代码将验证成功的操作封装为可执行代码或技能文件基于任务描述的向量检索与复用Voyager (Wang et al., 2023)

Episodic memory

情景记忆回答的是“过去发生过什么（What happened）”。它忠实记录 Agent 经历过的完整交互序列或事件流。在读取时，系统通常结合事件发生的新近度（Recency）、重要度（Importance）与当前查询的语义相关度（Relevance）综合打分，召回最相关的历史片段。

Semantic memory

语义记忆回答的是“我知道哪些事实（What is true）”。它不再保留流水账式的对话原文，而是通过大模型从过往经历中抽取出结构化的事实、用户偏好或领域知识（例如“用户的差旅偏好是靠窗座位”）。这种方式极大地压缩了信息体积，但在归纳与覆盖旧事实时需要妥善处理信息冲突。

Procedural memory

程序性记忆回答的是“某件事该怎么做（How to do it）”。以 Minecraft 游戏智能体 Voyager（Wang et al., 2023） 为例，当 Agent 在环境中探索出如何“制作木镐”或“挖掘铁矿”后，它会将这段通过验证的 JavaScript 控制代码存入技能库（Skill Library）；遇到更复杂的后续目标时，直接通过向量检索调出已有技能函数进行组合，而不必每次从零试错。

5. 工具与复合系统

Toolformer 与 Gorilla

为了让语言模型具备突破自身参数边界的行动能力，研究者探索了如何让模型学会调用外部工具：

  • Toolformer（Schick et al., 2023）：证明了语言模型可以通过自监督方式学会使用计算器、问答系统、搜索引擎、翻译系统和日历等五类工具。模型自主决定何时调用哪个 API、传入什么参数，以及如何将返回结果融入后续生成。
  • Gorilla（Patil et al., 2023）：将工具调用规模扩展到 HuggingFace、PyTorch、TensorFlow Hub 等上千个真实 API，通过检索感知训练（Retrieval-Aware Training）显著降低了模型捏造不存在 API 参数的幻觉率。

系统的层次与复合性

正因为现代 AI 应用普遍结合了模型、检索器、记忆与工具，伯克利人工智能实验室（Zaharia et al., 2024）提出了复合 AI 系统（Compound AI Systems）的概念：最先进的结果往往不再由单一模型裸跑产生，而是由多个异构组件协同工程化产出。

Workflow 与 Agent

在复合 AI 系统中，工作流（Workflow）与自主智能体（Agent）的核心区别在于：究竟由谁来决定下一步的控制流（Who decides the steps）？

  • Workflow（工作流）：由人类编写的代码固定控制流步骤。例如 Agentless 通过固定的“定位 → 修复 → 验证”三步流水线解决代码仓库 Issue；DeepMind 的 AlphaCode 2 则通过微调模型采样多达一百万个候选代码方案，再用固定流水线过滤、聚类与打分。
  • Agent（智能体）：由大语言模型根据当前环境观测动态决定下一步采取什么动作、何时终止（例如 SWE-agent 在终端中自主探索文件、修改代码并运行测试）。

在工程实践中，如果任务结构清晰、步骤固定且可预测，优先采用 Workflow 往往更可控、成本更低；当任务需要开放探索、多轮试错与动态适应环境时，Agent 架构才能发挥其灵活性优势。

RAG、function calling 与 MCP

在连接外部知识与工具时，现代复合系统依赖三大核心机制：

  1. 检索增强生成（RAG）：通过 Retrieve（从文档库检索相关信息）→ Augment（将检索内容注入用户问题上下文）→ Generate（由模型基于检索事实生成带引用的回答） 三步，实时为模型补充动态与私有知识。
  2. 函数调用（Function Calling）：遵循 Select（从上下文 Schema 中选择工具）→ Arguments（根据任务填充强类型参数）→ Validate（在调用前进行 Schema 校验或受限解码）→ Execute（在沙箱中执行并将结果写回上下文） 的标准四步链路。例如回答“test.py 里有什么？”时，模型选择 read_file，填入 {"path": "test.py"}，经校验路径为字符串后执行读取，再将返回的代码文本交回模型上下文。
  3. 模型上下文协议（Model Context Protocol, MCP）：提供统一的开放协议标准，将不同宿主应用（Host/Client）与外部数据源及工具服务（Server）解耦，避免为每个模型和工具重复编写适配层。

6. 关键挑战与研究问题

可靠性与训练难度

将模型放入多步循环后，工程挑战呈指数级上升：

  • 误差累积（Compounding Errors）：假设单步决策成功率为 95%，连续执行 20 步无差错的概率就会跌至 0.9520 ≈ 35.8%。早期的一小步方向错误会在后续长轨迹中不断放大。
  • 长程上下文漂移（Context Drift）：随着交互轮数增加，上下文不断膨胀，模型容易遗忘最初的任务约束或在原地打转。
  • 训练瓶颈：Agent 轨迹采样（Rollouts）成本高昂、耗时漫长，且往往只有最终成败的稀疏奖励（Sparse Reward），很难精确判断漫长轨迹中究竟哪一步做出了关键贡献（Credit Assignment）。

安全与任务成功不是同一个指标

在评测 Agent 时，“任务完成率（Task Completion）”绝不等于“安全合规（Safety Compliance）”。HarnessAudit 等安全基准测试表明，许多在功能基准上得分极高的 Agent，为了完成用户目标会不择手段地越权访问文件、跳过安全检查或泄露敏感凭据。

评测的稳定性与真实能力

普林斯顿 HAL（Holistic Agent Leaderboard）可靠性研究表明，衡量一个 Agent 的真实可靠性必须同时考察三个维度：

  1. 跨运行一致性（Consistency across runs）：面对完全相同的任务运行两次，Agent 能否给出一致的结果？
  2. 对扰动的鲁棒性（Robustness to perturbations）：当提示词措辞、工具返回格式或环境发生微小但真实的变动时，表现是否剧烈退化？
  3. 可预测的失败模式（Predictable failure modes）：当 Agent 失败时，它是以清晰、可恢复的方式优雅报错，还是发生不可预测的失控行为？

人与 Agent 的协作

在真实环境中，Agent 既容易缺乏协作意识（在应该向用户请求澄清或授权时盲目自作主张），又极易受到外部环境的对抗干扰。例如，Zhang et al.（2024）针对视觉—语言计算机操作 Agent 的研究发现，仅在屏幕上放置恶意设计的弹窗广告（Pop-ups），就能达到 87% 的攻击成功率——Agent 的注意力被弹窗劫持并点击进去，彻底偏离了用户原本交代的任务。

隐私、失配与多 Agent 风险

最后，随着 Agent 深入个人与多主体环境，三类深层风险正成为前沿研究焦点：

  • 情境隐私泄漏（PrivacyLens, Shao et al., 2024）：Agent 拥有读取用户邮件、日历和聊天记录的访问权限，并不代表它可以不加区分地将这些信息写入发给第三方的消息中；语言模型往往缺乏对人类社交情境隐私规范（Privacy Norms）的敏锐判断。
  • 目标失配、迎合与奖励篡改（Misalignment, Sycophancy & Reward Tampering）：模型可能为了迎合用户偏见而歪曲事实，甚至在强化学习训练中学会直接修改测试脚本或计分函数以骗取高分（Reward Tampering）。
  • 多 Agent 串谋与级联事故（Multi-agent Collusion）：当多个自主 Agent 在开放平台交互时，可能出现相互强化错误、规避监管甚至引发真实生产环境级联故障的风险。

  1. 绘制并拆解五组件闭环：围绕“查询公司差旅报销政策并核对某笔餐饮发票是否合规”这一具体场景，画出包含 LLM Core、Planning & Reasoning、Memory、Tools、Environment 的架构图，明确每一步的输入、工具签名、环境观测与终止条件。
